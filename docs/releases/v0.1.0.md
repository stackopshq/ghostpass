First tagged release of GhostPass. Until now, self-hosted instances ran the moving `main` image; `v0.1.0` gives a version to pin and to cite.

## For self-hosters

**Administration view.** List the administrators in `GHOSTPASS_ADMIN_EMAILS` (comma-separated). These accounts get an *Administration* section in the web app:

- open or close sign-up with one button. The choice is kept in the database. When sign-up is closed, the server refuses new accounts and the web app hides the sign-up link;
- every account, with its creation date, last sign-in and second factor;
- suspend an account (its sessions end at once, sign-in is refused) and reactivate it;
- delete an account and its vault, after typing its address again. The audit log keeps that an account was deleted, not which one.

The view shows metadata only: like the rest of the server, it cannot read a vault. An administrator cannot be suspended or deleted from the view; remove the address from `GHOSTPASS_ADMIN_EMAILS` instead.

**Pinning sign-up in your deployment files.** `GHOSTPASS_REGISTRATION=open` or `closed` fixes the state; the view then shows it without a button. Left empty (the default), the view decides. Any other value stops the server at startup, rather than guessing a security setting.

Environment variables are read when the server starts: after changing `.env`, run `podman compose -f compose.selfhost.yml up -d` again.

## Images

```
ghcr.io/stackopshq/ghostpass:v0.1.0        # API
ghcr.io/stackopshq/ghostpass:v0.1.0-web    # web app behind nginx
```

To run this version: `GHOSTPASS_TAG=v0.1.0` in `.env`, then `podman compose -f compose.selfhost.yml pull` and `up -d`.

## Upgrading

The database gains a `suspended_at` column on `users` and an `instance_settings` table; both are created automatically at startup. Back up your database before upgrading, as for any update.

## Not yet

The iOS and Android apps do not yet show a specific message for a closed registration or a suspended account; the web app does.
